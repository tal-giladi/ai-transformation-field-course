# IBM course 5 — Lead AI Change: Workforce Enablement and Adoption

Read 2026-11-02 (all video transcripts and readings via the logged-in session). Slug
`ibm-ai-workforce-enablement-adoption`. 4 modules, ~4 h. Note: Tal's account shows "Enroll" on this
course page, so the plugin pages redirect; the plugin itself was read from its public source (see
below).

Course-wide format: thinner than course 4. Each module = intro video, a "problem" story, a
"perspectives" video (4 roles), "Terms you should know", a concepts video, a "portable skill /
interview answer" video, an AI-graded assignment and (modules 1, 2, 4) a 15-min plugin. **No exercise
guide, no LabBook files, no expert demo, no coach role-play in this course.**

All plugins of the certificate are public single-page HTML files in
`github.com/ianmelchinger-lang/LeadTrans` (served at `ianmelchinger-lang.github.io/LeadTrans/…`),
e.g. `LeadTrans_C5_M1.html`, `LeadTrans_C5_M2.html`, `LeadTrans_C5_M4.html`. Pattern: a fact table,
fill 2–3 numbers, check, then "move the levers" sliders with no right answer.

## Module 1 — The Human Side of AI Transformation

- **Scenario/role.** Learner inherits a rollout (regional ops director / function head / team lead):
  all licences active, training complete, good survey scores; on the floor tickets still go to the
  old inbox and the old spreadsheet stays open; promised productivity not visible.
- **Concepts.**
  - "Poorly measured licence": access, exposure, reaction, adoption and value treated as one claim.
  - Adoption evidence ladder: reach the tool → learned → using appropriately → in the real
    workflow → better results; a green rung doesn't prove the next.
  - Adoption = sustained, appropriate use in real work; value realization is a separate question.
  - Psychological safety defined narrowly (can raise a question without punishment; not comfort,
    job security or trust in the tool); a 2026 single-company correlational study cited with limits.
  - Resistance as information: non-use, silence, workarounds are clues; six domains to check (role
    and workload; purpose and decision rights; capability and support; workflow and tool fit;
    quality, trust and risk; wider operating conditions). "We don't know yet" is legitimate.
  - The stall loop: concern → workaround → leaders read defiance → tighter mandate → less voice.
    "Read the signal, not the silence."
- **How-to given.** Only a loose sequence: observe without assigning motive, gather evidence from
  several sources, form a provisional explanation, choose one proportionate test. No steps for how to
  observe, what to ask, what data to pull.
- **Exercise.** Plugin "Sort the signals" (classify observations by what they prove). AI-graded
  assignment. No artifact.
- **Gaps.** How to actually walk the floor: observation protocol, interview/focus-group questions
  that surface workarounds safely, anonymous pulse survey design, how to read tool telemetry vs
  workflow data, how to run a "what's blocking you" session, how to protect people who speak up,
  how to write the diagnosis up for the sponsor.

## Module 2 — Change Management for AI

- **Scenario/role.** A drafting/document/forecasting tool loved by one team gets scaled to a whole
  BU with a go-live date; months later logins outnumber real use and teams use it inconsistently.
  Learner = change lead; perspectives from people partner (HR), frontline leader, product
  owner/sponsor.
- **Concepts.**
  - "Go-live is not the goal"; the unbalanced ledger (credit to sponsor, checking/correcting burden
    to frontline).
  - ADKAR (individual) and Kotter (organizational) — named and summarized in a paragraph each;
    "neither is compulsory".
  - Power–interest grid + "material-affectedness override" (any group materially affected in
    workload, job, privacy or trust gets real engagement regardless of quadrant).
  - Stakeholder communication and consultation plan: per group — message, messenger, channel,
    timing, feedback route; check legal/union consultation duties locally.
  - Appropriate adoption (can include deliberate non-use, escalation, restricted use).
  - Adoption milestones defined before launch: one each for real use, outcome/quality,
    oversight/exceptions, affected-group feedback — with meaning, owner and response.
  - The Adoption Map (stakeholders, real effects, knowns/unknowns, differentiated comms, engagement
    actions, indicators, decision rights: proceed / proceed with conditions / delay / redesign /
    stop).
- **How-to given.** The components of an Adoption Map are listed; no worked example, no template
  file, no demo.
- **Exercise.** Plugin "Change management for AI" (LeadTrans_C5_M2). AI-graded assignment.
- **Gaps.** No actual comms artifacts (announcement email, manager talking points, FAQ for "will
  this replace me?"), no change-impact assessment per role, no works-council/union consultation
  process, no champion network design, no launch-week runbook, no sponsor-coaching script, no
  example of a filled stakeholder map for a real rollout.

## Module 3 — Workforce Enablement and Reskilling

- **Scenario/role.** Customer-facing team: >90% course completion, good feedback, months later same
  spreadsheets and manual process; enablement team vs frontline manager disagree.
- **Concepts.**
  - "Untrainable moments" — on-the-job situations training alone cannot solve.
  - Train → transfer → sustain; delivered / demonstrated / applied gaps.
  - Capability stack: general AI fluency for most, domain application for some, technical depth for
    few, plus organizational infrastructure (process, tools, incentives, leadership).
  - Upskilling (current role) vs reskilling (new role); mobility as a separate metric.
  - Risk-informed delivery decision: job aid / guided practice for low-stakes; formal instruction,
    supervised practice and verification before unsupervised work for high-stakes.
  - Kirkpatrick 4 levels (reaction, learning, behavior, results); completion sits outside all four.
  - The Fluency Map: tasks that change → roles affected → gaps per role group → prioritized skills
    → method matched to risk → measures of application and performance.
- **How-to given.** The order of steps above, in one paragraph. No template, no example roles.
- **Exercise.** No plugin. AI-graded assignment only.
- **Gaps.** No task-level analysis method, no skills-gap survey or proficiency check, no
  role-by-role example curriculum, no session design (how to run a 60-minute hands-on AI training,
  exercises using the team's real work, prompt libraries, job aids), no practice environment setup,
  no manager-reinforcement kit, no budget/time estimates, no measurement instrument (observation
  checklist, work-sample review).

## Module 4 — Measure and Reinforce Adoption

- **Scenario/role.** Steering committee asks "is it working?"; nearly every seat activated; someone
  reports "130 of 200 = 65% adoption". Learner = AI program lead reporting upward; perspectives from
  ops manager, finance leader, executive sponsor.
- **Concepts.**
  - Goodhart's law on the adoption dashboard; prompt counts, session length, accepted outputs are
    not value.
  - Evidence layers: provisioning → successful access → qualified use → workflow integration →
    outcome.
  - Qualified-use rate = people with a defined meaningful use event ÷ opportunity-aware population
    (people genuinely expected to meet the task), over a window matching the work cycle.
  - Definitions stable but correctable (document changes, run old and new in parallel).
  - Adoption hypothesis (enablement → qualified use → recurring use → outcome); leading/lagging only
    relative to the chain; "sustained" = across enough real work cycles.
  - Verdicts: continue / correct / expand / retire / gather better evidence; "not yet" must be
    possible. Avoid surveillance and usage contests.
  - The Adoption One-Pager.
- **How-to given.** The rate formula and the layer definitions; plugin computes it.
- **Exercise.** Plugin "Build the honest adoption rate" (`LeadTrans_C5_M4.html`): claims-team drafting
  assistant, 200 licensed, 130 with an event, 40 with no real task, 110 who also did the required
  compliance review → 110 ÷ 160 = 68.8% vs the naive 65%; sliders for both assumptions.
- **Gaps.** Never touches real telemetry: what logs each tool exports (M365 Copilot usage reports,
  ChatGPT Enterprise/Claude admin analytics), how to join them with HR/task data to build the
  opportunity-aware population, how to define a qualified event in a log, privacy rules for usage
  monitoring (works councils, GDPR), no dashboard template, no sample one-pager.

## Course-level verdict

**Reuse as vocabulary:** adoption evidence ladder / layers; licence ≠ adoption ≠ value;
resistance as information + the six domains; power–interest grid with the material-affectedness
override; go-live is not the goal; train → transfer → sustain; capability stack; risk-informed
delivery decision; Kirkpatrick levels; qualified-use rate and opportunity-aware population; adoption
hypothesis; Adoption Map, Fluency Map, Adoption One-Pager as named artifacts.

**Fill (this is the weakest course of the four I read — almost all diagnosis, almost no doing):**
1. Field work to diagnose a stalled rollout: floor observation, safe interviews and focus groups,
   pulse surveys, reading tool telemetry next to workflow data.
2. Real change artifacts: change-impact assessment by role, stakeholder map filled for a case,
   announcement and manager talking points, "will AI replace me" FAQ, consultation with works
   councils/unions, champions network, launch-week runbook.
3. Designing and delivering training: task-based curriculum per role, a runnable hands-on session on
   the team's own work, job aids and prompt libraries, practice sandbox, manager reinforcement,
   proficiency checks.
4. Building the adoption dashboard from actual exported usage data joined to task/HR data, with
   privacy-safe rules, and a sample One-Pager.
5. Workflow redesign itself (changing the process so the tool is the path of least resistance) —
   named as a cause everywhere, never taught.
